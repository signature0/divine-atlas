## Description
On a 390px-wide mobile viewport the layout viewport inflates to **643px**, so
**every page has horizontal scroll on phones.** `window.innerWidth` reads 643
(despite `visualViewport` = 390), `document.documentElement.scrollWidth` = 643.

## Root cause
`app/globals.css:156` — `.topnav .links { display:flex; gap:18px; margin-left:auto; }`
The 9 nav links (Vault·Graph·Japanese·Greek·Norse·Egyptian·Slavic·Mesopotamian·
Artifacts) lay out in a single non-wrapping flex row ~549px wide. There is no
mobile breakpoint that wraps or hides them, so the nav forces the document to
643px and the whole page scrolls sideways.

## Repro
Playwright mobile context (390×844, isMobile): any route → `innerWidth=643`,
scrollWidth=643. The `.links` div measures 549px wide.

## Impact
First impression on the majority of visitors (mobile). Horizontal scroll reads as
broken/low-quality on a "high-end museum" product.

## Proposed fix
At a mobile breakpoint (e.g. `max-width: 720px`): allow `.topnav .links` to
`flex-wrap: wrap` + reduce `gap`/font-size, OR collapse into a hamburger
`<details>` menu. Add `overflow-x: hidden` on `<html>` as a safety net. Verify:
Playwright mobile context reports `scrollWidth === clientWidth` (no overflow) on
`/`, `/culture/japanese`, `/myths/gre-creation`.

## Acceptance
- No horizontal overflow at 390px on the 3 QA'd routes (qa-sweep mobile check PASS).
- Nav remains usable (links reachable) on mobile.
