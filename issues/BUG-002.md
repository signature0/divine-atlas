## Description
On a 390px-wide mobile viewport the layout viewport inflates to **643px**, so
**every page has horizontal scroll on phones.** `window.innerWidth` reads 643
(despite `visualViewport` = 390), `document.documentElement.scrollWidth` = 643.

## Root cause
`app/globals.css:156` — `.topnav .links { display:flex; gap:18px; margin-left:auto; }`
The 9 nav links (Vault·Graph·Japanese·Greek·Norse·Egyptian·Slavic·Mesopotamian·
Artifacts) lay out in a single non-wrapping flex row ~549px wide. There is no
mobile breakpoint that wraps or hides them, so the nav forces the document to
643px and the whole page scrolls sideways.

## Repro
Playwright mobile context (390×844, isMobile): any route → `innerWidth=643`,
scrollWidth=643. The `.links` div measures 549px wide.

## Impact
First impression on the majority of visitors (mobile). Horizontal scroll reads as
broken/low-quality on a "high-end museum" product.

## Proposed fix
At a mobile breakpoint (e.g. `max-width: 720px`): allow `.topnav .links` to
`flex-wrap: wrap` + reduce `gap`/font-size, OR collapse into a hamburger
`<details>` menu. Add `overflow-x: hidden` on `<html>` as a safety net. Verify:
Playwright mobile context reports `scrollWidth === clientWidth` (no overflow) on
`/`, `/culture/japanese`, `/myths/gre-creation`.

## Acceptance
- No horizontal overflow at 390px on the 3 QA'd routes (qa-sweep mobile check PASS).
- Nav remains usable (links reachable) on mobile.

## Fix (commit ad56810, 2026-09-13)
Per HANDOFF-003, wrap approach (no hamburger — all links stay visible, no JS):
1. `html { overflow-x: hidden }` — safety net so nothing else can force sideways
   scroll (sticky nav verified unaffected).
2. `.topnav .inner` and `.topnav .links` get `flex-wrap: wrap` at every width —
   the backstop that makes the ~549px link row incapable of inflating the
   layout viewport at any width (including 721-766px, which the mobile
   breakpoint alone would have missed).
3. `@media (max-width: 768px)`: links take a full-width row under the brand
   (`margin-left: 0; width: 100%`), tighter gap (18px → 8px 14px) and 0.7rem →
   0.6rem type; the bar grows via `min-height: 60px` + padding instead of a
   fixed 60px height. 768px = narrowest width where the single row still fits
   (brand + gap + ~549px links ≈ 719px + 48px container padding).
All values reuse the existing mono type scale / gap steps from
app/globals.css — no new design values.

Verified (temp `next start -p 3050` on the final build; prod :3002 untouched,
orchestrator redeploys): Playwright 390×844 isMobile — `scrollWidth ===
clientWidth === 390` on `/`, `/culture/japanese`, `/myths/gre-creation`
(previously 643); `innerWidth` reads 390 (was 643); all 8 nav links' rects
within the viewport (row width 342px = content width; nav height 110px =
brand row + wrapped links row); sticky nav top stays 0 after scrolling 2000px;
720/768/769/1024/1440px all `scrollWidth === clientWidth` with 0 clipped
links; desktop 1440 unchanged (60px single row, 549px links).
