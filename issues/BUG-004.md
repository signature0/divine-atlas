## Description
Pages whose hero art is a remote image (Met Open Access CDN, Wikimedia) take
**13-19 seconds** to settle in Playwright, and `networkidle` is never reached
(lazy-loaded images keep the network busy / never fire until scrolled). This is
why the first qa-sweep reported 8 false "NAV-ERR timeout" routes — the pages DO
eventually render (verified: titles present, images loading incrementally), but
they're slow to become visually complete.

## Repro (Playwright, 1280x900)
- `/deity/gre-poseidon` → load+settle ~19s, images 2/5 complete at check
- `/deity/jpn-sarutahiko` → ~14s, 1/3 complete
- `/myths/jpn-amaterasu-cave` → ~16s, 1/3 complete
- `/deity/gre-chaos` → >45s timeout (hero image stalled)

## Impact
Perceived slowness + possible CLS on mobile (images have width/height, but the
hero is remote). Not a correctness bug, but it degrades the "cinematic museum"
feel and makes QA flaky.

## Proposed fix
- Self-host or proxy the hero images (or at minimum `fetchpriority="high"` on the
  LCP hero, `loading="eager"` for above-fold art).
- Add a small placeholder/blur-up so the hero paints instantly.
- Confirm `loading="lazy"` + explicit width/height on below-fold figures.

## Acceptance
- Art-heavy pages visually settle < 5s on a throttled 4G profile.
- LCP hero paints without layout shift.
